About

From ledger systems to product R&D.

I'm a software engineer working mostly on backend services, integrations, and automation. A lot of my work involves changes that cross several services, components, or teams.

I’m a software engineer working primarily on backend and product systems. My path has moved from financial data pipelines and internal tooling to platform and integration work, enterprise product R&D, and applied ML and mobile systems.

At BCA, a missed batch edge case could become a reporting problem, so migrations needed recovery paths and review. In platform and integration work, gateway, environment, and service configuration had to show which system owned a setting. In product R&D, I trace a business rule across validation, configuration, and apply paths before changing it.

Teaching is connected to that engineering work rather than separate from it. When I explain an API, pipeline, or project architecture, I use a diagram, test, runbook, or example that lets someone else follow the inputs, failure paths, and expected result.
